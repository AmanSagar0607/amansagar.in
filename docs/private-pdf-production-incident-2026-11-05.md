# Private PDF production issue — November 5, 2026

## Findings

- The production Supabase project had only the portfolio CMS migration applied. The `public.portfolio_documents` table was missing, so document listing and metadata writes could not succeed.
- The Vercel project environment-variable metadata also had no `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, or `R2_BUCKET_NAME`. The private PDF store requires these settings before list, upload, or preview can run.

## Changes made

- Applied the additive document table migration and service-role grants to the production Supabase project. The table has RLS enabled and no public or authenticated role access; content bytes remain in private R2 storage.
- Matched the local migration filenames to the applied production migration versions so a future Supabase migration push will not try to create the table a second time.
- Updated document and preview API errors to report missing R2 configuration as HTTP 503 with the required variable names. Secret values are never returned.

## Remaining production setup

PDF upload and preview require R2 credentials from the Cloudflare account. Add `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `R2_BUCKET_NAME` to the Vercel project's **Production** environment, then redeploy. Keep the R2 bucket private. These credentials are not available in the connected Vercel project settings and cannot be inferred or generated by this repository.

## Verification

- Supabase migration history now includes both document migrations.
- `public.portfolio_documents` exists with RLS enabled and the expected schema.
- TypeScript, targeted ESLint, and `git diff --check` pass.
